tiny_ekf 错误报告
=================
测试日期: 2026-07-25
测试环境: gcc -std=c99 -Wall -Wextra -O2 (Linux x86_64) + musl-gcc (x86 musl)
测试结果: 22 passed, 0 failed (glibc 和 musl 均通过)

修复的 1 个 bug:

----------------------------------------------------------------------
Bug 1: restrict 指针别名 — vec_add/mat_sub 输入输出同指针
----------------------------------------------------------------------
位置: tiny_ekf.c:141, 149 (初版)
现象: 编译警告 "passing argument 3 to restrict-qualified parameter
      aliases with argument 1", glibc 下运行正常但 musl 下行为未定义。
原因: vec_add 和 mat_sub 的声明中 out 参数为 restrict,
      但调用时传入 ekf->x / I_KH 同时作为输入和输出指针:

         vec_add(ekf->x, dx, ekf->x, n);      // restrict 违规
         mat_sub(I_KH, KH, I_KH, n, n);       // restrict 违规

      restrict 的语义是"该指针是访问所指内存的唯一途径"。
      编译器可以假定输入和输出不重叠, 若重叠则优化可能产生
      错误结果 (如在循环中读到已被修改的值)。

修复: 改用手写循环, 避免 restrict 限定符冲突:

  初版错误:
    vec_add(ekf->x, dx, ekf->x, n);
    mat_sub(I_KH, KH, I_KH, n, n);

  修复后:
    for (int i = 0; i < n; i++)
        ekf->x[i] += dx[i];              // 明确的原地累加

    for (int i = 0; i < n * n; i++)
        I_KH[i] -= KH[i];                // 明确的原地减

  教训: 当矩阵库函数声明了 restrict 参数时, 原地操作不能用
        同一个指针同时做输入和输出。要么用临时数组中转,
        要么写手写循环 — 对 n≤12 的小维度, 手写循环更高效
        (省去一次 memcpy + 一次函数调用)。

----------------------------------------------------------------------
潜在问题 (未触发, 预记录)
----------------------------------------------------------------------

1. S 非正定 → 观测丢弃:
   当 Cholesky 4 级扰动 (1e-10→1e-8→1e-6→1e-4) 均失败时,
   ekf_update 返回 m 但不更新状态和协方差 (相当于本次观测被
   静默丢弃)。调用方应检查 P 是否在合理的数值范围内 — 如果
   协方差发散, 后续所有观测都可能触发此路径。

2. n×n 但 m×n / n×m 混合乘法:
   代码中有 mat_mul(H, ekf->P, HP, m, n, n) (m×n × n×n)
   和 mat_mul(K, R, KR, n, m, m) (n×m × m×m)。
   tiny_linalg 的 mat_mul 要求 m,k,n 参数分别对应左矩阵行数、
   左列数/右行数、右列数。混合维度的调用容易写错参数顺序 —
   已完成测试验证正确性, 但未来修改时常回检。

3. 数值 Jacobian 无处可用:
   与 tiny_opt 不同, EKF 没有数值 Jacobian 的支持。
   调用方必须提供解析的 Jacobian (F 和 H 回调)。
   如果用户不确定导数是否正确, 建议用数值差分在 PC 端交叉验证。
