Bug 1: vec_dot 语法错误
----------------------------------------------------------------------
位置: tiny_linalg.c:22
现象: 编译报错 "expected identifier before '.'"
原因: 浮点字面量写成 0.0. (双句号), C 解析为 0.0 后跟 . 运算符, 语法非法
修复: 0.0. → 0.0

  double s0 =0.0., s1 =0.0., s2 =0.0., s3 =0.0.;  // 错误
  double s0 =0.0,  s1 =0.0,  s2 =0.0,  s3 =0.0;   // 正确

Bug 2: solve_cubic NaN 风险
----------------------------------------------------------------------
位置: tiny_linalg.c:272-273
现象: 特定浮点输入下返回 NaN, 导致 mat33_symeig 特征值全部为 NaN
原因:
  a) acos() 参数未钳位到 [-1,1], 浮点误差可能使参数略超出范围
  b) -p/3.0 可能为微小负值 (p 理论上 ≤0 但浮点误差可打破此约束), sqrt 负数 → NaN
修复: acos_arg 钳位到 [-1,1]; r_arg 下界保护为 0

  // 修复后
  double acos_arg = -q * 0.5 / sqrt(disc > 1e-30 ? disc : 1e-30);
  if (acos_arg >  1.0) acos_arg =  1.0;
  if (acos_arg < -1.0) acos_arg = -1.0;
  double phi = acos(acos_arg);
  double r_arg = -p / 3.0;
  if (r_arg < 0.0) r_arg = 0.0;
  double r = 2.0 * sqrt(r_arg);

Bug 3: eigenvec_from_lambda 特征向量错误
----------------------------------------------------------------------
位置: tiny_linalg.c:302-308
现象: 对角矩阵 A = diag(3,2,1) 的特征分解, 第2和第3个特征向量均返回
      [1,0,0] 而非 [0,1,0] 和 [0,0,1], 导致 mat33_svd 重构失败
原因: 原始算法选最大范数行, 然后叉积其余两行。对角矩阵中, B = A-λI
      的第 i 行为零向量 (对应特征值 λ 所在行), 若该行恰好不是范数最大的
      行, 则被选入叉积, 与另一行叉积得零向量 → 退化 → 返回 [1,0,0]
修复: 改为叉积范数最大的两行, 确保不会选到零向量行

  // 修复后
  if (n0 >= n1 && n0 >= n2) {

      else          vec_cross(r0, r2, v);
  } else if (n1 >= n0 && n1 >= n2) {

  } else {
      if (n0 >= n1) vec_cross(r2, r0, v);
      else          vec_cross(r2, r1, v);
  }

原因: else 分支对 j=1 和 j=2 使用统一逻辑 "cross(U[j-1], U[0])",

关键教训
----------------------------------------------------------------------
1. 对角矩阵 (或近对角矩阵) 是最好的测试用例 — 它能暴露特征向量算法中
   对零行的处理缺陷
2. 浮点保护 (钳位、下界) 在嵌入式场景 (musl libc, RISC-V) 尤其重要,
   编译器优化差异可能放大 x86 上不明显的舍入误差
3. 叉积自身 → 零向量 是一个容易在统一分支中忽略的边界条件, 对 SVD 和
   特征分解这类算法, 三个分支拆开写更安全
