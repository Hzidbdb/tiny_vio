tiny_opt 错误报告
=================
测试日期: 2026-07-25
测试环境: gcc -std=c99 -Wall -Wextra -O2 (Linux x86_64)
测试结果: 22 passed, 0 failed

修复的 3 个 bug:

----------------------------------------------------------------------
Bug 1: mat_cholesky 输入/输出同指针导致输入被清零
----------------------------------------------------------------------
位置: tiny_opt.c:155 (初版)
现象: lm_solve 第一步返回 -2 (λ爆炸), 所有测试 FAIL
原因: mat_cholesky(A, L, n) 的实现第一行是 memset(L, 0, n*n*sizeof(double)),
      当时传了 mat_cholesky(H_aug, H_aug, n) — 输入和输出同一个指针,
      先清零再读 → H_aug 全零 → Cholesky diag=0 → 返回 -1 非正定 →
      λ 在 20 次重试中翻倍到 2e16 → 溢出 → 返回 -2。
      λ 直到 2e16 时才触发出错返回, 中间每次重试都在读一个零矩阵。
修复: 引入独立的 H_aug 工作数组, mat_copy(H, H_aug, n, n) 后对 H_aug 对角加 λ,
      再 mat_cholesky(H_aug, L, n) — A 和 L 分属不同数组。

  初版错误:
    mat_copy(H, H, n, n);                    // H_aug 还没创建, 用 H 自己
    H[i*n+i] += lambda;                     // 原地修改的是 L (同指针)
    mat_cholesky(H, H, n);                  // 先清零 H, 再读...全零!

  修复后:
    mat_copy(H, H_aug, n, n);               // 拷贝到独立 H_aug
    H_aug[i*n+i] += lambda;                 // 在 H_aug 上加阻尼
    mat_cholesky(H_aug, L, n);              // A=H_aug, L=L, 不同指针

  教训: mat_cholesky 的"非破坏性"指的是不破坏 A, 但要求 A 和 L 不同指针。
        如果它们相同, memset(L) 会同时销毁 A。调用约定文档应该明确这一点。

----------------------------------------------------------------------
Bug 2: break 作用域错误 — 接受步后退出外层迭代循环
----------------------------------------------------------------------
位置: tiny_opt.c:229 (初版)
现象: 第一次接受步后 lm_solve 立即返回 -1 (未收敛), 所有测试 FAIL,
      但 Rosenbrock 显示 iter=0, lambda 很小 — 说明只走了一步就退出了。
原因: 初版用 for(iter=0; iter<max_iter; iter++) 作外层循环,
      内层用 for(retry=0; retry<20; retry++) 做 λ 增大重试。
      接受步后的 break 写在了 for(iter) { ... for(retry) { ... break; } } 的
      外层 — C 的 break 只退出最内层, 但因为代码块嵌套缩进不清晰,
      break 实际在外层 for(iter) 内, 内层 for(retry) 之后,
      所以它退出了外层迭代循环而非内层重试循环。
修复: 外层改用 while(iter < max_iter), 内层保持 for(retry),
      接受步后 break 正确退出内层 retry 循环, 继续 while 的下一次迭代。

  初版错误 (简化):
    for (iter = 0; iter < cfg.max_iter; iter++) {
        for (int retry = 0; retry < 20; retry++) {
            if (accept) {
                break;   // 误区: 以为退出 retry 循环
            }
        }                 // 实际: retry 循环到这里已经退出了,
                          // break 在这里退出的是 iter 循环!
    }

  修复后:
    while (iter < cfg.max_iter) {
        for (int retry = 0; retry < 30; retry++) {
            if (accept) {
                iter++;
                break;    // 明确退出 retry 循环, 回到 while 条件判断
            }
        }
    }

  教训: 双层循环用同款 for 时, break 的归属容易混淆。
        while+for 组合让每层的退出点更清晰。

----------------------------------------------------------------------
Bug 3: ρ≈0 拒绝实际下降的合法步
----------------------------------------------------------------------
位置: tiny_opt.c:192 (初版)
现象: Rosenbrock 测试: y 坐标误差 ~1.6e-6 (勉强通过 1e-6 阈值),
      线性 LS 测试失败 — λ 过大时步长极小, 实际 cost 下降但 ρ=0
      (成本差和预测差都四舍五入为零), 被当作无效步拒绝。
原因: 增益比 ρ = (cost - cost_trial) / pred,
      当 λ 很大时, 预测步的 cost 下降 ≈ 0, pred ≈ 0,
      实际 cost 下降也 ≈ 0, 两个极小值相除结果是 0.0 (double 精度丢失)。
      ρ > 0.0 为假, 步被拒绝, λ 继续增大 → 死循环。
修复: 加备选条件 `|| cost_trial < cost` — 只要实际代价下降,
      就接受这一步, 无论 ρ 算出来多大。

  初版错误:
    if (rho > 0.0) {      // λ 大时 ρ==0.0, 条件为假
        接受步...
    } else {
        拒绝; λ *= ν;     // λ 更大 → 更严重的精度丢失
    }

  修复后:
    if (rho > 0.0 || cost_trial < cost) {  // 实际下降即接受
        接受步...
    }

  教训: 在接近收敛时, double 精度的限制会让基于比率的判断失效。
        用绝对值条件 (cost_trial < cost) 做最终决策更鲁棒。

----------------------------------------------------------------------
关键教训
----------------------------------------------------------------------
1. 永远不要向 mat_cholesky 传相同的 A 和 L 指针 — 其实现先清零输出再读输入。
   需要独立的 H_aug 和 L 数组。调用约定应在注释中明确警告。

2. 双层迭代循环 (外层 LM + 内层 λ 重试) 中的 break 归属必须明确。
   while+for 嵌套比 for+for 更不易出错, 因为每层的终止/继续条件更清晰。

3. 浮点精度在优化接近收敛时是真实问题:
   - 成本差接近 0 时 ρ 计算无意义
   - 用绝对值条件 (cost_trial < cost) 兜底, 不依赖比率的数值精度
