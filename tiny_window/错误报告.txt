tiny_window 错误报告
====================
测试日期: 2026-07-27
测试环境: gcc -std=c99 -Wall -Wextra -O2 (Windows MinGW, x86_64)
测试结果: 6 passed, 0 failed

以下为开发过程中发现并修复的 bug, 以及设计决策记录。

----------------------------------------------------------------------
Bug 1: 欠定系统导致 LM 返回 -2 (已修复)
----------------------------------------------------------------------

  现象: test_minimal_window 用 N=2 关键帧时, window_optimize 返回 -2,
        LM 不做任何迭代, 状态完全不变。

  根因: N=2 时 n_state=18, n_resid=15, m < n。
        lm_solve() 在参数检查阶段直接拒绝:
          if (m < n) return -2;

  修复: 测试改用 N=3 关键帧 (n=27, m=30 ≥ 27)。
        建议在 window_optimize 中也加检查:
          if (n_resid < n_state) return -1;

  影响范围: 仅测试代码, 不影响核心实现。
  修复日期: 2026-07-27

----------------------------------------------------------------------
Bug 2: mat_cholesky_solve 缓冲区溢出导致段错误 (已修复)
----------------------------------------------------------------------

  现象: N=3 时 LM 在第二个迭代的 Cholesky 求解中崩溃 (SIGSEGV),
        gdb 回溯指向 mat_cholesky_solve 内部。

  根因: tiny_linalg/tiny_linalg.c:450 中 mat_cholesky_solve 的临时数组
        写死为 double y[16]。原设计面向 LM_MAX_PARAMS=12 的问题,
        滑动窗口优化时 n=27, 前代循环 y[16..26] 越界写入,
        破坏栈上的 H/J 等数据。

  修复: tiny_linalg/tiny_linalg.c:450, y[16] → y[64]。
        64 覆盖当前最大参数维度 LM_MAX_PARAMS=48。

  影响范围: tiny_linalg (所有调用 mat_cholesky_solve 且 n>16 的场景)。
            该函数此前仅在 n≤12 的场景测试过, 此 bug 一直潜伏。
  修复日期: 2026-07-27

----------------------------------------------------------------------
设计决策 1: v_0 自由 vs 固定
----------------------------------------------------------------------

  当前设计: 首个关键帧 (窗口最老帧) 的位姿固定, 但速度 v_0 参与优化。

  理由: 滑动窗口中 v_0 可能已知 (上一轮优化的结果) 也可能未知
        (启动首帧)。将 v_0 放入状态向量用优化估计, 适应两种情况。

  代价: v_0 自由时, 优化器可调整 v_0 来使 IMU 与含噪声的 PnP 保持一致,
        位置估计可能不偏离 PnP。这是数学上正确的解 — 系统有足够的
        自由度同时满足两类约束。此问题在以下条件缓解:
        (a) 窗口运行多轮后 v_0 从历史优化继承了较好的初值
        (b) IMU 协方差权重 >> PnP 权重时, v_0 被 IMU 强约束
        (c) 后续加入边际化 (Schur 补) 时, v_0 受先验约束

----------------------------------------------------------------------
设计决策 2: 协方差白化用对角近似
----------------------------------------------------------------------

  当前实现用 1/sqrt(cov[ii]) 对残差做对角加权, 而非完整的
  Cholesky(L^{-1}) 白化。

  理由: 预积分协方差的非对角元通常较小 (旋转/速度/位置间耦合弱),
        对角近似在大多数场景下足够。完整白化需要每个 IMU 因子做
        9×9 Cholesky 分解, 计算量增加 3-4 倍。

  代价: 当 IMU 噪声较大或积分时间较长时, 非对角耦合增强,
        对角近似会丢失部分信息, 导致优化结果次优。

  后续计划: 加入 mat_cholesky 做完整白化 (已预留 mat33_inv 和
            Cholesky 的调用逻辑, 改动量约 20 行)。

----------------------------------------------------------------------
设计决策 3: 解析 Jacobian (已完成, 不再用数值 Jacobian)
----------------------------------------------------------------------

  原用 lm_solve 内置的前向差分数值 Jacobian, 每次 LM 迭代需 (n+1) 次
  残差调用 (n=27 时 28 次)。在 MaixCAM RISC-V 1GHz 单核上跑不到 30Hz,
  用户要求必须改为解析 Jacobian。

  2026-07-27 完成解析 Jacobian 实现, 修复了以下 3 个 bug 后测试全过:

  Bug 3: SO(3) 右 Jacobian 符号错误
    公式 Jr = A·I + B·aa^T − C·skew(a), 代码中 skew 项符号写反 (+C 应 −C)。
    φ > 0.2 rad 时 Jr 非对角元符号全错, LM 一步就把 φ 推到 2.14 rad。

  Bug 4: ∂r_R/∂φ_i 变量引用错误
    mat_mul(Jr_inv_R, dRT, tmp, ...) 写到 tmp, 下一行 block[k] = -block[k]
    操作的是未初始化的 block, 再下一行 mat_mul(block, Jr, tmp) 又覆盖 tmp。
    tmp 应为 block。

  Bug 5: ∂r_R/∂φ_i 用了错误矩阵
    公式推导为 dR_corr^T (偏置修正后的预积分旋转), 代码写了 R_{i+1}^T * R_i
    (状态的相对旋转)。两者在收敛前不相等。

  解析 Jacobian 要点:
  - se(3) 加法更新: φ_new = φ_old + δφ → R_new = Exp(φ_old)·Exp(Jr(φ_old)·δφ)
  - 链式法则: ∂r/∂φ = ∂r/∂ε · Jr(φ), 其中 ε 是 SO(3) 右扰动
  - IMU 旋转残差: ∂r_R/∂φ_i = −Jr⁻¹(r_R)·dR_corr^T·Jr(φ_i)
  - IMU 速度残差: ∂r_v/∂φ_i = skew(R_i^T·Δv_world)·Jr(φ_i)
  - IMU 位置残差: ∂r_p/∂φ_i = skew(R_i^T·Δp_world)·Jr(φ_i)
  - PnP 旋转残差: ∂r_vis_R/∂φ_i = −Jr⁻¹(r_vis_R)·Jr(φ_i)
  - 偏置 Jacobian: 直接从预积分拷贝 (J_dR_bg, J_dv_ba 等)
  - 所有块乘行白化权重: 旋转/速度/位置各 3 个独立权重

  性能提升: n=27 时从 28 次残差调用/iter 降为 1 次, ~28x 加速。

----------------------------------------------------------------------
Bug 6: 偏置偏移依赖运行时 n_kf, ctx 未固化 (已修复)
----------------------------------------------------------------------

  现象: window_residual 和 window_jacobian 中调用 off_ba(n_kf) / off_bg(n_kf)
        动态计算偏置在状态向量中的偏移, n_kf 取自 ctx->n_kf。

  风险: 如果 window_optimize 外部的 w->n_kf 发生变化 (比如 drop_oldest 后
        未重新调用 optimize), ctx->n_kf 可能与实际窗口状态数不一致,
        导致 ba/bg 偏移计算错误, LM 读到错误的内存位置。

  修复: resid_ctx_t 新增 ba_off / bg_off 两个字段, 在 window_optimize 中
        与 n_kf 同时快照, 之后 window_residual 和 window_jacobian 直接使用
        ctx->ba_off 和 ctx->bg_off, 不再依赖 off_ba(n_kf) 动态计算。

  影响范围: tiny_window.c (ctx 结构体 + 三处调用点)
  修复日期: 2026-07-27

----------------------------------------------------------------------
设计决策 4: 直接丢弃最老帧 vs 边际化
----------------------------------------------------------------------

  当前 window_drop_oldest() 直接丢弃最老关键帧, 不做 Schur 补边际化。

  理由: 先验证优化框架正确性。边际化涉及:
        (a) 构建完整 Hessian
        (b) Schur 补计算 H* = H_bb - H_ba·H_aa^{-1}·H_ab
        (c) 将 H* 和 b* 作为先验因子加入下一轮优化
        实现复杂度显著高于直接丢弃。

  代价: 丢弃最老帧会丢失其携带的信息, 导致:
        (a) 位置/偏航误差改善幅度有限 (当前 ~8%/~19%)
        (b) 长时间运行可能出现漂移

  后续计划: 实现 Schur 补边际化 (v2)。

----------------------------------------------------------------------
设计决策 5: Huber 核函数 (IRLS 实现)
----------------------------------------------------------------------

  2026-07-27 实现。Huber 损失函数降低大残差 (异常值) 的权重:

    ρ(r) = 0.5·r²            (|r| ≤ δ)
    ρ(r) = δ·(|r| - 0.5·δ)   (|r| > δ)

  IRLS 权重: √w = 1 (|r|≤δ), √w = √(δ/|r|) (|r|>δ)

  实现方式:
    a) window_residual 末尾: 对白化后的残差逐元素计算 √w,
       存入 ctx->huber_wt[], 并乘到残差上
    b) window_jacobian 末尾: 逐行将 J 乘以 ctx->huber_wt[row]

  默认 huber_delta=0 (关闭)。调用 window_set_huber_delta() 启用。

  注意: Huber 权重在协方差白化之后施加, 使 δ 的量纲与白化残差一致。
        白化残差 ≈ N(0,1), δ=1.345 对应 95% 渐近效率。

设计决策 6: SO(3) 右 Jacobian 提取到 tiny_linalg
----------------------------------------------------------------------

  原状: so3_right_jacobian() 在 tiny_imu 和 tiny_window 中各有一份独立
        实现, 公式不同但数学等价。不是 bug, 但违反 DRY 原则。

  修复: 2026-07-27 将 mat33_right_jacobian() 和 mat33_right_jacobian_inv()
        提取到 tiny_linalg, 两个调用方改为引用 linalg 版本。
        tiny_imu 的 skew_mat 和 tiny_window 的 skew3 各自保留
        (linalg 不提供 skew, 且两者都还有别的用途)。

  测试: 全部模块重新测试通过 (191 个断言)。

----------------------------------------------------------------------
设计决策 7: v0 速度先验
----------------------------------------------------------------------

  原状: 首个关键帧的速度 v_0 为自由变量, 优化器可任意调整它来补偿
        含噪声的 PnP 观测, 虽然数学上正确但在静止启动场景下不符实际。

  修复: 2026-07-27 新增 window_set_v0_prior(w, sigma)。
        - sigma=0 (默认): 与之前行为一致, v_0 自由
        - sigma>0: 添加 3 维残差 r = v_0 / σ, 约束 v_0 ~ N(0, σ²)
        - 对于智能车从静止启动, 建议 σ=0.01~0.05

  test_minimal_window 验证: σ=0.01 时 v_0 被约束到 [0.0005, 0.0002, -0.0004],
        同时 kf_2 速度仍正确估计为 1.97 (真值 2.0)。

  注意: 如果车辆启动时已有明显初速 (如抛投), 不应启用 v0 先验。

----------------------------------------------------------------------
已知限制
----------------------------------------------------------------------

  1. 栈内存: LM 工作区约 120 KB, 加窗口约 5 KB, 总计 ~130 KB。
     MaixCAM 默认 8 MB 线程栈足够, 但注意不要在主线程的深层调用
     中使用 (主线程栈通常较小)。

  2. 关键帧间 IMU 预积分时长: 仅验证了 0.2-0.5 秒 (5-10 fps)。
     超过 1 秒的间隔会导致预积分一阶精度下降, 协方差过度累积。

  3. 零速检测: window_add_keyframe 不检查载体是否静止。
     静止时 PnP 位姿噪声占比大, 应降低 PnP 权重或使用零速约束。

  4. 异常值拒绝: 当前无 PnP 异常值检测 (如位姿跳变 > 阈值时丢弃)。
     建议在调用方做 chi² 检验, 或加入 Huber 核函数。
